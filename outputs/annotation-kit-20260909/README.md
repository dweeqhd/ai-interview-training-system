# AI 面试数据标注员填写包

本填写包用于第一批软件开发岗模拟面试数据：5 名参与者，每人回答 3 道固定问题，共 15 条录音。

## 1. 包内文件

- `AI面试数据标注总表.xlsx`：主要填写文件，已经预填 15 条录音任务、题目和匿名编号；
- `csv_templates/00_录音任务清单.csv`：15 条录音的编号、题目、时长和文件名；
- `csv_templates/01_录音元数据模板.csv`：负责人记录录制环境、设备、时长和授权范围；
- `csv_templates/02_转写校对模板.csv`：标注员保存原始 ASR 文本和人工修正文本；
- `csv_templates/03_停顿标注模板.csv`：每发现一个停顿填写一行；
- `csv_templates/04_内容证据标注模板.csv`：逐项判断题目要点、STAR 和事实证据是否出现；
- `csv_templates/05_人工评分模板.csv`：每条录音填写一次六维人工评分；
- `csv_templates/06_最终共识评分模板.csv`：两名标注员复核后由负责人填写；
- `录音使用同意书模板.md`：录音前由参与者确认授权范围。

Excel 是首选填写方式。CSV 是备用模板，也方便后续程序读取。不要同时在 Excel 和 CSV 中重复填写同一份标注，以免出现两个版本。

## 2. 如何分发

1. 负责人保留一份未填写的原始模板；
2. 把 `AI面试数据标注总表.xlsx` 分别复制给两名标注员；
3. 第一名标注员把文件重命名为 `AI面试数据标注表_L01.xlsx`；
4. 第二名标注员把文件重命名为 `AI面试数据标注表_L02.xlsx`；
5. 两名标注员独立完成，不查看、不讨论对方结果；
6. 标注完成后分别交回负责人；
7. 负责人保留两份原始结果，再组织分歧复核并填写共识结果。

只把对应的匿名录音发给标注员。不要通过公开网盘分享，不要在文件名、表格和聊天消息中记录真实姓名、学号、手机号。

## 3. 三道固定问题

| 题目编号 | 问题 | 建议时长 |
|---|---|---:|
| `dev_basic_01` | 请用一分钟进行自我介绍，并说明你应聘软件开发岗位的优势。 | 45～90 秒 |
| `dev_project_01` | 请介绍一个你参与过的项目，并说明你负责的部分。 | 60～120 秒 |
| `dev_project_02` | 项目中最困难的技术问题是什么，你是如何解决的？ | 60～120 秒 |

参与者可以提前准备关键词提纲，但不能照完整稿件朗读。第二题和第三题可以使用同一个真实且不涉及敏感信息的项目。

## 4. 如何命名录音

统一格式：

```text
参与者编号_题目编号_录制次数.扩展名
```

例如：

```text
U001_dev_basic_01_T01.m4a
U001_dev_project_01_T01.m4a
U001_dev_project_02_T01.m4a
```

- `U001`～`U005`：匿名参与者编号；
- `T01`：第一次自然回答；
- 如果以后录制改进版本，使用 `T02`；
- 推荐保存为 WAV 或 M4A；WebM、MP3、OGG、FLAC 也可由系统处理；
- 不得使用真实姓名作为文件名。

原始录音由负责人放入项目的私有目录：

```text
data/raw_audio/dev/
```

收到的标注文件放入：

```text
data/annotations/private/
```

这两个目录均不得提交到公开 Git 仓库。

## 5. Excel 中每张表填写什么

### 填写说明

供标注员查看规则，不填写。

### 录音任务

列出 A001～A015 对应的参与者、问题、建议时长和标准文件名。负责人确认实际文件名和任务状态，标注员一般不修改。

### 录音元数据

由负责人填写，不需要两名标注员重复填写。主要记录：

- 实际音频时长；
- 安静室内或轻微噪声等录制环境；
- 手机、电脑或耳麦等设备类型；
- 是否允许用于开发、匿名统计和课堂播放；
- 异常情况。

`允许开发`、`允许匿名统计`、`允许答辩播放`是三项不同权限，不能互相代替。

### 转写校对

每条录音填写一行：

1. 把系统识别文本复制到“原始 ASR 文本”；
2. 完整听一遍录音；
3. 在“人工修正文本”中逐字修正；
4. 保留“嗯、呃、额、那个、就是”等语气词；
5. 保留重复、改口和未说完的句子，不能润色成书面范文；
6. 听不清时填写 `[听不清 00:23]`，并在“听不清片段”中记录。

### 停顿标注

每发现一个停顿填写一行。表中为每条录音预留 10 行，不够时复制该录音最后一行并继续编号；未使用的预留行把“行状态”改为“未使用”。

1. 不查看系统自动停顿结果，先独立人工标注；
2. 记录约 0.3 秒以上、能够感知到的停顿；
3. 记录开始秒、结束秒和持续时间；
4. 类型选择“句间”“句内”“无效噪声”或“无法判断”；
5. 开头和结尾为录制保留的安静时间不算停顿；
6. 咳嗽、敲击声等写成“无效噪声”，`是否有效`填写“否”；
7. 某条录音没有需要标注的停顿时，保留第一行，行状态选择“未发现停顿”，其余预留行选择“未使用”。

时间以秒填写，建议保留两位小数，例如开始 `12.30`、结束 `13.05`、持续 `0.75`。

### 内容证据

逐行判断指定要点是否在回答中真实出现：

- `题目要点`：是否覆盖题目要求；
- `STAR结构`：项目题中的 S 情境、T 任务、A 行动、R 结果；
- `事实成果`：个人职责、具体行动、结果或验证、量化事实。

“出现”必须能在修正文本中找到证据。把最短且能说明问题的原话复制到“证据原文”。没有明确证据时选择“否”；确实无法判断时选择“无法判断”。关键词出现不代表一定满足要求，需要结合上下文判断。

### 人工评分

每条录音填写一行：

- 题目相关性：0～20；
- 结构完整性：0～20；
- 事实与成果：0～20；
- 语速表现：0～10；
- 停顿表现：0～15；
- 语气词与时长：0～15。

先独立听完并查看人工修正文本，再评分。不得根据声音好听与否、性别、年龄、口音、方言、外貌或性格印象加减分，也不得填写“是否录用”。

### 共识评分

仅由负责人在两名标注员都提交后填写。以下情况应共同复听：

- 20 分项目相差超过 4 分；
- 15 分项目相差超过 3 分；
- 10 分项目相差超过 2 分；
- 一人认为存在停顿、另一人认为不存在；
- 同一停顿边界相差超过约 0.3 秒。

不得用共识结果覆盖 L01、L02 的原始文件。

### 评分标准

给出六个评分维度的统一锚点。评分前应先阅读，遇到边界情况在评论中写明依据。

## 6. 建议工作顺序

```text
负责人编号并录音
→ 填写录音元数据
→ 系统生成 ASR 文本
→ L01、L02 分别校对转写
→ 独立标注停顿和内容证据
→ 独立进行六维评分
→ 负责人检查完整性
→ 对较大分歧共同复听
→ 保存最终共识结果
```

第一批 15 条全部作为开发集，`split` 填写 `dev`。它们用于调整规则和阈值，不能作为最终测试集，也不能据此声称系统达到某个通用准确率。

## 7. 提交前检查

标注员提交前确认：

- 文件名中包含自己的标注员编号 L01 或 L02；
- 15 条录音均完成转写校对和人工评分；
- 停顿预留行已经改成“有效停顿”“无效噪声”“未发现停顿”或“未使用”；
- 内容证据的每行均选择“是”“否”或“无法判断”；
- 所有分数都在允许范围内；
- 没有填写真实姓名、学号、手机号；
- 没有删除或覆盖原始 ASR 文本；
- 没有查看另一名标注员的结果。
