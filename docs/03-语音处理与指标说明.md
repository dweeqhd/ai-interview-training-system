# 阶段 3：语音处理与指标说明

## 1. 处理链路

```text
浏览器录音或上传文件
  → 格式、大小、时长校验
  → 保存原始文件（不进入 Git）
  → FFmpeg 转为 16 kHz 单声道 PCM WAV
  → FSMN-VAD 划分语音片段
  → Paraformer 中文转写
  → CT-Punc 标点恢复与句级时间信息
  → 计算语速、停顿、语气词等客观指标
  → SQLite 保存任务状态、文本和指标
```

分析任务有 `queued`、`processing`、`completed`、`failed` 四种状态。当前使用 FastAPI 后台任务，适合课程项目的单机演示；多人并发和断点恢复需要后续改为独立任务队列。

## 2. 音频约束

- 支持 WAV、WebM、MP3、M4A、OGG、FLAC；
- 单个文件不超过 25MB；
- 回答时长为 5–180 秒；
- 标准化结果为 16kHz、单声道、16 位 PCM WAV；
- 原始文件和标准化文件均存放在 Git 忽略目录；
- 文件使用随机 UUID 命名，不使用真实姓名。

## 3. 模型与本机环境

| 组件 | 固定版本或模型 | 用途 | 本机占用 |
|---|---|---|---:|
| PyTorch / torchaudio | 2.11.0+cpu | CPU 推理运行时 | 约 0.2GB 加依赖 |
| FunASR | 1.4.15 | 语音分析框架 | Python 包 |
| ModelScope | 1.40.0 | 模型下载与本地缓存 | Python 包 |
| Paraformer | `iic/speech_seaco_paraformer_large_asr_nat-zh-cn-16k-common-vocab8404-pytorch` | 中文转写与时间信息 | 约 0.93GB |
| FSMN-VAD | `iic/speech_fsmn_vad_zh-cn-16k-common-pytorch` | 语音活动检测 | 小于 0.01GB |
| CT-Punc | `iic/punc_ct-transformer_cn-en-common-vocab471067-large` | 中英文标点恢复 | 约 1.11GB |

模型缓存位于 `models/modelscope`，不提交到 Git。FunASR 工具代码与各模型权重的许可证并不一定相同；公开展示或发布前，团队必须再次查看每个模型卡中的许可证与使用条件，并记录模型修订版本。

## 4. 指标如何计算

### 4.1 回答总时长

读取标准化 WAV 的采样帧数和采样率：

```text
总时长（秒） = 总采样帧数 ÷ 采样率
```

### 4.2 有效说话时长

将 VAD/句级时间段的持续时间求和。它排除首尾静音以及语音段之间的静音，比直接使用总时长更适合计算语速。

### 4.3 有效语速

```text
表达单位数 = 中文字符数 + 英文/数字连续词组数
有效语速 = 表达单位数 ÷ 有效说话分钟数
```

该指标不是语言学意义上的严格“词数/分钟”，页面必须显示单位和计算说明，不能把它包装成绝对能力分数。

### 4.4 停顿

相邻语音段之间的空隙作为候选停顿：

- 小于 500ms：暂不计入明显停顿；
- 500–1499ms：明显停顿；
- 大于等于 1500ms：长停顿。

输出停顿起止位置、持续时间、总次数、长停顿次数、最长停顿和停顿占比。阈值只是初始实验参数，后续必须使用人工停顿标注校准。

### 4.5 语气词

首版统计“嗯、呃、额、啊、那个、就是、然后”等词的出现次数。部分词在具体语境中可能是正常连接词，因此只展示客观计数，不直接等同于扣分。

## 5. 人工数据如何用于改进

1. 使用停顿标注表记录人工认为的句内停顿、句间停顿和无效噪声；
2. 对 300ms、500ms、800ms 等候选阈值计算查准率、查全率和 F1；
3. 在开发集选阈值，在测试集只做一次最终评估；
4. 比较“总时长语速”和“VAD 有效时长语速”与人工流畅度评分的相关性；
5. 记录每次参数、数据划分和结果，形成可复现的算法改进实验。

## 6. 当前限制

- CPU 首次加载模型需要等待，单条回答的推理时间要通过实测记录；
- 当前任务在 Web 服务进程内运行，服务意外关闭后不会自动恢复排队任务；
- ASR 错字会影响语速单位和语气词统计；
- 句级时间边界不等同于人工语义停顿；
- 未经人工数据校准，不应给出“语速好/坏”或通用面试能力结论。
