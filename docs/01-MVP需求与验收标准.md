# 阶段 1：MVP 需求与验收标准

## 1. 目标用户

主要用户为准备软件开发、软件测试或相近技术岗位面试的大学生。

## 2. 核心场景

用户选择一道面试题，录制 60–120 秒中文回答。系统完成转写与分析，用户根据报告再次作答，并看到前后变化。

## 3. 第一版功能优先级

### P0：必须完成

1. 题目列表与题目详情；
2. 浏览器录音、试听、重录、上传；
3. 音频格式校验与任务状态；
4. 中文转写与时间戳；
5. 语速、停顿、语气词、时长；
6. 关键词、STAR 和量化成果分析；
7. 综合报告；
8. 历史记录。

### P1：时间允许再做

1. 用户修改 ASR 转写文本后重新分析；
2. 岗位热词维护；
3. 管理员题库页面；
4. 同一道题的两次回答对比。

### P2：仅作为未来工作

1. 根据简历自动追问；
2. 实时语音面试；
3. 数字人；
4. 多岗位大规模题库；
5. 手机应用。

## 4. 报告维度

总分 100 分，仅用于训练参考：

| 维度 | 分值 | 必须展示的证据 |
|---|---:|---|
| 题目相关性 | 20 | 命中和缺失的回答要点 |
| STAR 结构 | 20 | S/T/A/R 是否出现及对应原句 |
| 事实与成果 | 20 | 个人行动、技术细节、数字成果 |
| 语速适配 | 10 | 有效语速和整体表达速度 |
| 停顿表现 | 15 | 句内停顿次数、最长停顿、时间位置 |
| 语气词与时长 | 15 | 语气词统计、有效表达时长 |

## 5. 功能验收标准

### 题库

- 至少有 15 道软件开发岗问题；
- 每题包含类别、关键词、STAR 要求、建议时长和人工审核状态；
- 题库草案必须经团队人工复核后才能标记为 approved。

### 录音

- 支持开始、停止、试听、重录和提交；
- 单条回答建议 60–120 秒，硬上限 180 秒；
- 空音频、过短音频、超长音频和格式错误有明确提示。

### 语音分析

- 返回完整转写文本；
- 返回有效说话时长和音频总时长；
- 返回有效语速和整体表达速度；
- 返回明显停顿、句内停顿、最长停顿和停顿占比；
- 返回语气词及次数；
- ASR 错误不得直接判定为用户表达错误。

### 内容分析

- 结论必须关联问题和岗位；
- STAR 判断必须引用回答中的证据句；
- 缺少量化结果时只建议补充，不要求编造；
- 大模型异常时仍能输出规则版基础报告。

### 历史记录

- 刷新页面后报告仍存在；
- 用户只能查看自己的记录；
- 至少能对比最近两次回答的核心指标。

## 6. 非功能验收

- 本地开发环境可按 README 重现；
- 不在代码和日志中保存 API 密钥；
- 真实音频和人工标注不推送到公开仓库；
- 关键接口有自动测试；
- 分析失败时保留错误阶段和用户可读提示；
- 答辩前准备一份离线录屏。

## 7. 阶段 1 完成定义

- 范围、评分维度和验收标准成文；
- 有 15 道题库草案；
- 有录音元数据、人工评分、停顿标注模板；
- 有录音使用同意书模板；
- 有明确的 Git 和 AI 协作规范；
- 尚不要求完成代码或安装环境。
